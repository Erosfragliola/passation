- **Ce qui reste** : `/api/maquette` et toutes les règles de `public/js/regles.js` :
  - étages = CA, fenêtres allumées = effectif, arbres = marge, archétype = code NAF ;

- **Ce qui est remplacé** : `public/js/maquette.js` (géométrie) et `public/js/scene.js` (rendu, chronologie), dans la

- **Ce qui s'ajoute** :

## 1. Architecture des fichiers

| Fichier | Rôle |
|---|---|
| `public/js/cloche/rendu.js` | moteur de rendu : AgX, environnement PMREM, chaîne de post-traitement, qualité adaptative, compteur `?debug` |
| `public/js/cloche/materiaux.js` | textures procédurales sur canvas : noyer (anneaux et veinage), plâtre, balsa, lichen, cuivre brossé, avec les normal maps et roughness maps qui en dérivent |
| `public/js/cloche/vitrine.js` | décor fixe : table en feutre, socle en noyer chanfreiné et sa moulure, plaque en cuivre et ses vis, cloche en verre, poussière dorée, spot de musée |
| `public/js/cloche/diorama.js` | construit le diorama à partir des données (même entrée que l'ancienne `construireMaquette`) : volumes arrondis, fenêtres avec petits-bois, lueurs intérieures, personnages, arbres en lichen, accessoires de l'archétype |
| `public/js/cloche/choregraphie.js` | la séquence de 9 s, l'interruption, l'orbite au repos, le rattachement des étapes de la frise |
| `public/js/cloche/passation.js` | les mains au trait (SVG superposé, tracé `stroke-dashoffset`), liées au défilement |
| `public/js/votre-maquette.js` | inchangé dans son rôle : recherche, frise, valeur. Il appelle la nouvelle scène avec la même API (`respirer`, `construire`, `terminer`, `exporter`) |

Tout le JavaScript 3D reste chargé **après** le premier rendu de la page, comme aujourd'hui. Le champ SIREN est utilisable
immédiatement.

En **mobile** (390 px), la cloche passe au-dessus du texte, cadrée plus serrée. La séquence dure 5 s et les mains entrent
en bas de l'écran.

## 3. Rendu

- `toneMapping = AgXToneMapping`, `outputColorSpace = SRGBColorSpace`. L'option `physicallyCorrectLights` demandée n'existe
  plus depuis Three r155 : l'éclairage physique est le comportement par défaut, rien à activer.
- Environnement : `RoomEnvironment` passé par `PMREMGenerator` ; il produit les reflets sur le verre et le cuivre.
- Éclairage :
  - `SpotLight` principale à 2 700 K, ombres `PCFSoftShadowMap` en 2048 px, ouverture serrée comme dans une vitrine ;
  - contre-jour froid et faible derrière la cloche ;
  - `HemisphereLight` très faible pour le remplissage ;
  - lueurs : plans émissifs derrière les vitrages, et 3 `PointLight` seulement, pour les 3 fenêtres principales.
- Post-traitement, dans cet ordre :
  1. N8AO ;
  2. bloom sélectif (fenêtres, cuivre, poussière) ;
  3. tilt-shift, c'est-à-dire une profondeur de champ en bande, mise au point sur la façade ;
  4. vignettage, grain léger et correction chaude ;
  5. SMAA.
- Verre : `MeshPhysicalMaterial` (transmission 1, épaisseur 0,4, ior 1,5, rugosité 0,03, teinte ambrée très légère),
  avec un liseré de fresnel sur le bord.

## 5. Performance, repli, accessibilité

- **Budget JavaScript 3D** : environ 300 Ko gzip, sous la limite de 600 Ko :
  - Three.js actuel : 195 Ko gzip ;
  - `postprocessing` et `n8ao` : environ 90 Ko, à mesurer ;
  - code Passation : environ 20 Ko.
- **Qualité adaptative** : sous 45 i/s pendant 2 s, on coupe d'abord le tilt-shift, puis l'AO, puis les ombres douces.
  Le mode `?debug` affiche les i/s et le palier de qualité actuel.
- **Mobile** :
  - verre simulé par un fresnel, sans transmission physique ;
  - pas d'AO, ombres en 1024 px, 4 personnages au maximum.
- **`prefers-reduced-motion`** : image finale fixe, frise en texte, ni rotation ni particules.
- **Sans WebGL** : illustration SVG de l'archétype dans un cadre doré, et la frise.
- **Canvas** : `aria-hidden="true"`. La valeur, la frise et le texte de la plaque existent en HTML. L'export PNG est
  conservé et montre la cloche.

## 6. Points à trancher avant de coder

1. **Police de la plaque et des grands chiffres.** Le prompt demande une serif. Vous avez demandé Geist partout.
   Proposition : plaque gravée en **Geist capitales espacées**, valeur en **Geist** grand corps. Si vous préférez une
   serif à ces deux endroits seulement, dites lesquels.
2. **Blender.** Il n'est pas installé : il faudrait `brew install --cask blender`, environ 1 Go.
   - **Avantages** : l'éclairage et l'AO précalculés dans les textures donnent une vraie finesse, surtout pour le lichen
     et les personnages.
   - **Inconvénients** :
     - une étape de fabrication de plus ;
     - le décodeur Draco (environ 100 Ko) ;
     - des fichiers GLB à maintenir.
   - **Ma recommandation** : commencer **en code procédural**, sans rien installer. Je juge ensuite sur les captures et
     ne passe à Blender que si le critère « photo ou rendu ? » n'est pas atteint.
3. **Ordre de travail.** Ce chantier s'intercale avant le bloc B (dépôt de la liasse) du parcours validé. On le fait
   maintenant, ou après le bloc B ?
4. **Honnêteté sur le critère d'acceptation.** Hésiter entre une photo et un rendu en temps réel dans un navigateur est
   atteignable sur une capture fixe en bureau (matériaux mats de maquettiste, AO, profondeur de champ). En animation
   et sur mobile, ce sera moins le cas. Je vous montrerai les captures sans les embellir.

## 8. Réalisation (10/11/2026)

Décisions prises faute de réponse explicite (recommandations du plan) :
- **Typographie** : Geist partout, capitales espacées gravées sur la plaque, Geist Mono pour « DEPUIS ».
- **Fabrication** : tout en code procédural, sans Blender.
- **Passation** : la main gauche soulève **l'ensemble par le socle** (et non la cloche seule) et le tend à la main droite. C'est
  bien l'entreprise qui passe de main en main. Le geste se joue au défilement et s'inverse si l'on remonte.
- **Accessoires proposés** : retenus tels quels.

Écarts techniques assumés :
- `PCFSoftShadowMap` a été retiré de Three r186 : on utilise `PCFShadowMap` avec `shadow.radius` 7 (ombres douces, disque de
  Vogel).
- **Environnement** : `RoomEnvironment` faisait des taches carrées sur le verre. Il est remplacé par un studio photo construit
  en code :
  - grande boîte à lumière chaude ;
  - bande verticale ;
  - contre-jour ;
  - réflecteur de face et carton bas.
- **Bloom** : « sélectif » par luminance (seuil HDR 0,92). Seuls les vitrages allumés, les reflets du cuivre et la poussière
  dépassent le seuil.
- **Textures** : calculées dans un Web Worker (`textures-worker.js`), donc aucun octet téléchargé et la page n'est pas bloquée.
  Les shaders sont compilés avec `compileAsync`.
- **Chargement** : à 25 % de visibilité de la section, pendant un moment calme. En attendant, une image fixe de la cloche est
  affichée (`img/photos/cloche-repos-*.webp`, 20 et 36 Ko).

Mesures (Chrome sans écran, GPU Metal, ce Mac) :
- **Lighthouse local** :
  - mobile : performance 99, accessibilité 100, bonnes pratiques 100, SEO 100 (TBT 0 ms, LCP 2,0 s) ;
  - ordinateur : 100 / 100 / 100 / 100.
- **Images par seconde** : 60 i/s (plafond de l'affichage) en qualité complète, sur ordinateur comme en émulation mobile. Le
  chiffre sur un vrai MacBook Air M1 reste **à confirmer** avec `?debug`.
- **Chargement de la 3D** : prête 0,8 s après l'arrivée sur la section, avec 2 tâches longues (0,10 s et 0,20 s) masquées par
  l'image fixe.
- **Poids de la 3D** (compressé) :
  - Three.js : 191 Ko ;
  - `rendu3d.js` (postprocessing et N8AO) : 158 Ko ;
  - code de la cloche : 35 Ko ;
  - total : environ 384 Ko, pour un budget de 600 Ko.

Ce qui reste perfectible :
- en gros plan, le diorama se lit encore comme un rendu, alors que le socle, le verre et la lumière passent pour une photo ;
- le cadrage mobile montre la plaque floue (tilt-shift) ;
- le verre simulé sur mobile garde un léger voile.
